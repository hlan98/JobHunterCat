## 核心模块

### `agent/main.py` — 主程序（7,230 行）
Tk 桌面 UI + 全流程编排。所有流程的调度中枢：方案生成、投递循环、HR 监听、
LLM 接管、停止总结、看板事件推送。

### `agent/pet_bridge.py` — 桥接层
stdin/stdout JSON 协议，把 Python 内核接给 Electron 壳。
负责 `cmd:` 命令分发与 `type:` 事件发射。

### `boss/boss_apply.py` — BOSS 自动投递核心（975 行）
强制用 DrissionPage 接管本地 9222 端口浏览器。
岗位收集 → 卡片预过滤 → JD 读取 → 评分 → 打招呼。

### `boss/boss_chat.py` — HR 消息监听 + 自动发简历（1,458 行）
轮询聊天页会话，识别五类信号：
- **要简历**（系统卡片 + 文本两种形态）→ 自动同意 + 选附件简历 + 发送
- **拒绝** → 发礼貌致谢
- **面试邀请** → 提示用户接管，不自动回复
- **系统模板** → 识别后不回复
- **普通对话** → 兜底分支，不自动回复，只写提醒

> **判定顺序**固定为「面试邀请 → 拒绝 → 要简历 → 系统模板 → 普通对话（兜底）」，
> **不是**按上面的列举顺序。
> **只有「要简历」和「拒绝」会真的发出消息**，其余三类一律只提醒、不代答。

### `agent/shared.py` — 公共内核（2,310 行）
配置读写、日志、LLM 客户端、评分逻辑、浏览器接管、DOM 工具。

### `agent/ledger.py` — 动作账本（106 行）
每次关键动作（打招呼 / 发简历 / 跳过 / 失败）写一条 JSONL 到 `run/ledger/`。
**投递结果记录**由此承担（原 `outcomes.json` 方案已废弃）。
纯追加、写失败静默，绝不影响主流程。

### `agent/doctor.py` — 环境自检（197 行）
逐项检查 Python / 依赖 / 配置 / LLM，缺什么、怎么补。

### `agent/skill_entry.py` — CLI 入口（556 行）

### `desktop/src/` — 桌面壳（Electron）
- `main.js` — 主进程、窗口管理、事件转发、Python 进程拉起
- `renderer.js` — 桌宠渲染（透明窗、状态素材切换）
- `chat.js` / `chat.html` — 对话窗（打字机、状态行、命令路由）
- `dash.html` — 看板（总览 / 运行中 / 报告 / 设置）

## 当前正在开发

### Personal Job Memory — ✅ 已实现
`run/job_memory.json` 已在实际运行中积累数据。
下面数字来自作者本机 **2026-09-18 ~ 09-24 连续 7 天**的真实运行
（`run/` 不入库，所以你 clone 下来看到的是空壳，首次运行后自行累积）：

```json
{
  "v": 1,
  "jobs": [ ... 1,346 条评估记录，去重后 524 个岗位 ... ],
  "keyword_stats": { ... 18 个关键词的命中统计 ... },
  "updated": "..."
}
```

> **口径提示**：`jobs` 是**记录条数**，不是岗位数 —— 同一岗位在不同关键词、不同轮次下
> 会各记一条，所以条数大于实际岗位数（这份数据里 1,346 条对应 524 个去重岗位）。
> 同理，动作账本 `run/ledger/` 里的条数是**动作次数**，去重需按「岗位名 + 公司」。

相关实现：`_load_job_memory` / `_save_job_memory` / `_fold_report_into_job_memory` /
`_job_memory_path`（`main.py`）。每轮投递结束把报告折叠进记忆。

### Strategy Engine — 🚧 部分实现
目前只有**摘要层**回灌：`_recent_runs_brief(limit=5)` 把最近几轮投递摘要
（约 350 tokens）注入方案修订的 prompt，让 LLM 改方案时能看到历史表现。

**尚未实现**：把 `keyword_stats` / `jobs` 的完整统计做成显式策略引擎，
独立于 prompt 之外做决策（如自动淘汰低效关键词、自动调阈值）。

### 历史结果 → 下一轮求职方案 — 🚧 部分实现
链路已通（记忆 → 摘要 → prompt → 新方案），但**粒度粗**：
只传摘要不传统计明细，LLM 看不到"哪个关键词一直 0 达标"这类结构性信息。

- 记录并对比每轮方案的达标率，形成可回溯的策略时间线
